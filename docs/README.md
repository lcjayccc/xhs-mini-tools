# 小红书小工具项目文档

项目资料的唯一入口。平台约束和 Agent 分工见仓库根目录 `AGENTS.md`，这里不重复。

## 资料导航

| 文件或目录 | 何时读取 |
|---|---|
| `CURRENT.md` | 每次开工时；各工具的当前版本、平台状态、下一步 |
| `TODO.md` | 排期、查看未关闭事项时 |
| `DECISIONS.md` | 需要知道某个决定的理由、放弃的方案或重开条件时 |
| `CHANGELOG.md` | 发版、查某个版本改了什么时 |
| `tasks/` | 只读当前任务的文件夹；任务复杂到需要规格或过程记录时才建，命名 `T-xx-简述/` |
| `research/` | 选题调研和开发全景（HTML），按需打开，不作当前事实来源 |

## 目录约定

```
小红书工具/
├── AGENTS.md        项目规则：平台硬约束、协作流程
├── <工具名>/        每个工具一个目录，内容就是 zip 的内容（index.html 在根）
├── docs/            本目录
├── releases/        打包好的 zip，不进 git
└── .review/         Agent 协作过程材料（截图、Gemini 规格与原始回答），不进 git
```

- 工具目录里只放会进 zip 的文件。说明、截图、规格一律不放进去，免得混进包里。
- 新工具：新建 `<工具名>/`，在 `CHANGELOG.md` 加一节，在 `CURRENT.md` 加一行。

## 版本管理

- **每个工具独立版本**，按 `主版本.次版本.修订号`：
  - 新功能、明显的界面变化：升次版本（1.0.0 → 1.1.0）
  - 只修 bug：升修订号（1.1.0 → 1.1.1）
  - 玩法大改、存储数据不兼容：升主版本
- **版本号以 `CHANGELOG.md` 为准**。`redapp submit` 填的 version 必须和它一致；代码里不另写版本号。
- **发版顺序**：
  1. 改动提交到 git，`CHANGELOG.md` 写好本版条目
  2. 打 tag：`<工具名>/v<版本>`，例如 `darkroom/v1.1.0`
  3. 按 `minitool-zip-builder` 的 `zip-artifact-spec.md` 打包到 `releases/<工具名>-<版本>.zip`，跑包里的 `audit_artifact` 审计脚本
  4. 上传、手机扫码预览、送审（按 `redapp-cli` 的流程；每一步对外写入都要 Kaisa 授权）
  5. 送审结果回写 `CHANGELOG.md` 和 `CURRENT.md`
- zip 不进 git：需要旧版本的包时，从对应 tag 检出源码重新打包。

## 任务管理

- 待办只记在 `TODO.md` 一处，编号 `T-xx` 递增不复用。
- 状态词：待处理 / 进行中 / 验证中 / 完成 / 取消。完成和取消的条目在下一次收口时移除，结论吸收进 `CURRENT.md`、`CHANGELOG.md` 或 `DECISIONS.md`。
- 时间一律写北京时间（本机时钟是 UTC−4，写之前先换算）。
