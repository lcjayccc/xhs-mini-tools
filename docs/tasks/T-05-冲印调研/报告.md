# T-05 冲印技术调研：从专业冲印的角度审视现有实现

汇总：Claude，2026-11-20（北京时间）。来源：Gemini Deep Research（引用 334 个来源，原文 `.review/t05-research/gemini-deep.txt`）、Claude 联网搜索、Claude 对 `film.js` 的代码阅读。来源等级：A 官方文档、B 权威二手、C 社区和个人、D 体验观察；**推论**和**未核实**单独标出。

## 结论

1. **现有实现确实粗糙，而且问题出在机制上，不在参数上。** 显影浓淡只看时间和平均晃动；「显影不匀」是一张 4×5 的随机格子，和用户怎么晃无关；漏光和沾灰是抽签贴图。真实暗房里，这些痕迹都由药水怎么流决定。
2. **可以真正模拟药水流体，而且能在小红书容器里跑。** 做法是把实时流体模拟（Stable Fluids）和「显影液消耗、溴离子抑制」的化学模型耦合起来：用户晃动驱动流场，流场决定每个位置换药快慢，换药快慢决定那里显影多快。显影不匀、溴化物拖影、边缘锐化线（Mackie lines）、涌浪痕都会**从模型里自己长出来**，不需要贴图（B，Gemini 综合 GPU Gems 第 38 章、Filmulator 和暗房化学文献提出的简化模型）。
3. **性能可行，但必须分档降级，且必须真机实测。** 流场只需 64×64 网格（低频量），显影密度图 256×256，出片时再按原图分辨率合成。Gemini 给的单帧耗时（低端机约 5～6 ms）是它按指令数估算的，**没有真机数据**，Chrome 61 上半浮点渲染能否用也取决于具体机型。

## 真实冲印的关键机制（只列和产品相关的）

| 机制 | 真实情况 | 来源 |
|---|---|---|
| 显影液消耗与溴离子抑制 | 银盐还原时消耗紧贴相纸的显影液，并释放抑制显影的溴离子。不搅动就形成「耗尽边界层」，暗部显影卡住、发灰；搅动的作用是把废液冲走、把新药送回来 | B（Kodak 感光测定手册、暗房化学文献，经 Gemini 汇总） |
| 溴化物拖影 | 富含溴化物的废液比重大，顺重力下沉，沿途抑制显影，留下**竖向**条纹 | C（Photrio 论坛、CineStill 帮助中心；论坛对条纹是变亮还是变暗有分歧） |
| 涌浪痕 | 搅得太猛，高速液流冲过边缘，**顺着搅动方向**留下显影过度的条带。和拖影的区别：拖影总是竖的（重力），涌浪痕顺水流 | B/C（CineStill 帮助中心） |
| 边缘锐化（邻接效应） | 明暗交界处，亮区的新鲜药液渗进暗区边缘、暗区的溴离子渗进亮区边缘，形成一对细亮线和细暗线，看起来更锐 | B（Wikipedia: Mackie line） |
| 固定节奏搅动 | 只沿一个方向、恒定节奏晃，会形成重复流型，留下规律条纹；暗房的做法是轮换方向、加点随机 | C（DOFMaster 教程） |
| 气泡斑 | 相纸入药时附着气泡，挡住药液，留下边缘锐利的圆形白斑（相纸上是白点） | B/C |
| 显影时间响应 | 入药后有一段几乎不变的诱导期，然后暗部先浮现，中间调和高光依次出来；**相纸必须显透**，提前捞出黑位发灰无力，泡太久高光蒙灰 | B（Ilford 相纸资料、Kodak Dektol 说明） |
| 定影不足 | 开灯后残余银盐见光自还原，照片泛粉紫并持续变暗 | B |
| 暗房痕迹的黑白极性 | 挡住放大机光线的东西在相纸上变**白**（底片上的灰尘印成白点）；让相纸额外受光的变**黑**（相纸漏光是黑边）。粗糙的模拟器常把这个弄反 | B（Gemini 汇总的暗房资料） |
| 胶片观感 | 影调由 H&D 特性曲线（趾部、直线部、肩部）决定；光晕（halation）是强光穿过片基反射回来，核心橙黄、外缘深红；颗粒在中间调最明显、极暗和极亮处衰减 | B（Dehancer 光晕文章、Kodak 资料、Newson 2017 颗粒论文） |

## 现有实现的差距

| 现象 | 现在怎么做（`film.js` / `app.js`） | 真实情况 | 差距 |
|---|---|---|---|
| 显影程度 | 全图一个数值 `dev`，按时间和平均晃动增长 | 每个位置的显影速度由局部药液决定 | 大：没有空间差异 |
| 显影不匀 | 4×5 随机格子放大，乘以 `uneven`（平均晃动的反面） | 由流场决定，拖影、涌浪、斑驳各有方向和位置规律 | 大：和用户操作无关 |
| **照片上的阶梯状色环** | 只预算 16 档显影查找表，「不匀」按 8×8 像素块取档，相邻块落在不同档就出现阶梯（Claude 读代码定位，D：截图里可见） | — | 现有 bug，任何方案都要修 |
| 颗粒 | 每像素 `Math.random()` 白噪声，强度只和 `dev` 有关 | 中间调最强、两端衰减；有颗粒形状 | 中 |
| 漏光 | 30% 概率，随机位置贴一块橙色径向渐变 | 应由操作引起（如开灯时机、安全灯超时） | 中：颜色方向对（彩色片背面漏光偏红橙），触发方式不对 |
| 沾灰、定影斑 | 随机贴图 | 灰尘印成白点；定影不足开灯后泛粉紫变暗 | 中 |
| 影调 | S 曲线 + 抬黑位 + 暖高光，16 档 | H&D 曲线，诱导期，先暗部后高光 | 中 |
| 光晕 | 无 | 胶片质感的标志之一 | 缺失 |
| 显影过程画面 | 灰度 canvas 用 CSS `filter` 调对比和亮度、透明度渐显 | 先暗部后高光逐步浮现 | 中 |

一个设计层面的事实：**彩色相纸在真实暗房里不能在红色安全灯下冲**（要全黑操作；B，Kodak 暗房照明指南）。我们「红灯下冲出彩色照片」是有意的魔法设定，保留没问题，但如果以后做「专业模式」，要区分黑白和彩色。

## 技术路线

**三个场耦合**（每帧）：

1. **流场**（64×64）：用户输入注入推力 → 平流 → 求压力 → 投影，药盘四壁反弹。输入来源：手指划药盘（已有）、陀螺仪（容器提供，经 `bridge.js`）。
2. **药液浓度场**：显影液浓度和溴离子浓度，随流场平流、横向扩散，并和「上方药池」交换；**交换速度随局部流速增大**，这是连接流体和化学的关键。
3. **显影密度场**（256×256）：每个位置的显影速度 = 温度系数 × 显影液浓度 ÷（1 + 抑制系数 × 溴离子浓度）×（目标密度 − 当前密度）。目标密度来自照片亮度。

开灯出片时：把定格的密度图放大到原图分辨率 → H&D 曲线转亮度 → 色彩映射表 → 颗粒（中间调最强）→ 光晕（1/4 分辨率模糊高光，偏红橙叠回去）。

**分档**（Gemini 估算，未实测）：

| 档位 | 条件 | 流场 | 显影图 |
|---|---|---|---|
| 1 | 支持半浮点渲染的中高端机 | 96～128 | 512 |
| 2 | WebGL 1 低端机（半浮点或 8 位打包） | 64 | 256 |
| 3 | 没有 WebGL，用 Canvas 2D | 24～32（CPU） | 256 |
| 4 | 前几十帧低于 20 fps | 32，不解压力，只做平流 | 256 |

**WebGL 1 / Chrome 61 的坑**（B，Gemini 引用 Chromium issue 40615157 等）：不要用 WebGL 2（老 Mali 驱动会黑屏）；半浮点渲染目标要用 4×4 测试纹理实测能否渲染，不能只看扩展是否存在；没有半浮点线性过滤时要在着色器里手写双线性插值；失败时退回 8 位纹理，用两个通道拼 16 位精度，避免小增量被舍入成 0。

## 待核实和风险

- **陀螺仪不是倾角（已核实，A：小工具在线文档 §3.14、§4.1，2026-11-19 版）**：容器**没有加速度计**，网页的加速度计、设备运动和朝向接口全部禁用；唯一的传感器是平台陀螺仪，回调给的是绕三轴的**角速度**（rad/s，文档原话「不是姿态角」），最快 60 ms 一帧（`interval: 'ui'`），需要客户端 9.50 以上。因此流体输入改为：角速度和手指划动转成药液里的冲力；想要「倾斜后药水流向一边」，只能对角速度做带衰减的积分来估算倾斜（不衰减会漂移）。
- **性能数字是估算**：所有毫秒数都来自 Gemini 的指令数模型，开工前要先在一台安卓 8.1 级别的真机（或创服模拟器）上跑一个最小流体原型做基线。
- **WebGL 在容器里的实际表现未实测**：规范允许 WebGL，但要求「必须控制 GPU 资源并提供运行时降级」（`minitool-zip-builder` 的 performance-budget.md）。
- **没有现成的同类产品**：Gemini 没找到「实时流体驱动显影化学」的 H5 案例（Filmulator 是桌面 RAW 编辑器，用的是静态扩散）。差异化是机会，也意味着没有可以直接照抄的实现。
