请深度调研：**暗房冲印的真实物理和化学过程，以及如何在手机网页上逼真地数字模拟它**。

背景：我们在做一个手机上的「暗房冲印」小游戏（小红书小工具，离线 H5）。用户选一张照片，在红色安全灯下模拟冲洗：晃手机或手指划药盘让显影液流动 → 捞出 → 按住定影 → 开灯看成片。冲洗得好不好决定成片效果。目前的实现比较粗糙：显影浓淡只是一个随时间增长的数值，「显影不匀」是一张随机放大的 4×5 明暗格子，和用户怎么晃完全无关；漏光、沾灰是随机贴图。我们想做一次质的提升，让药水流动真正决定显影结果。

请覆盖这些方面，每个结论附来源链接：

1. **黑白放大冲印的完整流程**：曝光（放大机、相纸反差等级、局部遮挡和加光）、显影、停显、定影、水洗；每一步的作用，做错会出现什么可见的结果。
2. **显影液和搅动对影像的影响**：显影液怎样在相纸表面消耗和补充；搅动不足、搅动过猛、单方向搅动分别产生什么痕迹（显影不匀、条纹和拖影、边缘效应、气泡斑点等），这些痕迹在画面上长什么样、出现在哪里、有没有规律。温度、时间、药水浓度、药水疲劳的影响。
3. **彩色冲印（RA-4 相纸、C-41 负片）**和黑白的区别；不同胶片和相纸的观感特征（颗粒、光晕 halation、色偏、影调曲线、暗部和高光的表现）。
4. **其他真实的暗房痕迹**：漏光、定影不足、水洗不足、指纹、划痕、灰尘、过度曝光和曝光不足在相纸上的样子。
5. **数字模拟的技术路线**：实时流体模拟（如 Jos Stam 的 Stable Fluids、WebGL 流体模拟的开源实现）能否用来驱动「局部显影速度」；胶片颗粒合成、光晕、色彩映射表（LUT）、影调曲线的业界做法；已有的「暗房模拟」或「胶片模拟」网页、游戏、App 案例。
6. **手机网页的性能约束**：目标环境是安卓 8.1 起的 WebView（Chrome 61），只能用 Canvas 2D 和 WebGL 1，不能用 WebAssembly、Worker、WebGL 2 必须有回退；流体网格多大、每帧多少计算在低端机上可行，怎样降级。

最后给出：**我们应该模拟哪些物理现象、按价值和实现难度排序的建议清单**。
