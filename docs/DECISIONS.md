## D-01 三个 Agent 的分工：Gemini 网页版做前端，Claude 总控，Codex 只读审查

- 日期 / 决定人：2026-11-19 / Kaisa
- 状态：试行中（流程细节在 `AGENTS.md`「协作流程」）
- 决定：Claude 拆任务、写规格、把 Gemini 的输出写回文件并自查，`bridge.js` 和 `film.js` 由 Claude 自己改；Gemini 网页版负责 HTML / CSS 和界面交互 JS；Codex 以 Orca worker 只读审查 diff。写代码的人不验收自己的代码。
- 理由：Kaisa 想利用 Gemini 的多模态和前端能力，也不想浪费 Gemini 的额度。Gemini CLI 个人账号已停服、Antigravity 无权限，只剩网页版；网页版读不到文件、也没法在容器里测试，所以容器逻辑和图像算法不交给它。
- 首个任务的结果（darkroom 1.1.0）：Gemini 两轮生成共约 5 分钟，没违反平台约束，视觉提升明显；有一处诊断和实现不一致，引入 3 个小 bug。Claude 没有做同一份 UI，所以「Gemini 前端比 Claude 强」**还没有结论**。
- 放弃：Gemini 包揽全部实现（容器逻辑返工风险最高）；Claude 一个人实现、Gemini 只做视觉验收（Kaisa 想让 Gemini 写代码）；Claude 浏览器自动化之外的 Gemini 接入（CLI 和 Antigravity 都没有权限）。
- 重开条件：拿到 Gemini CLI 或 Antigravity 的权限；连续几个任务里 Gemini 的界面需要 Claude 大量返工；或者做一次 Gemini 和 Claude 同一份规格的正面比试，结果明显偏向一方。

## D-03 拆成两个工具：暗房冲印店专注玩法，另做「废片救星」，共用出片引擎

- 日期 / 决定人：2026-11-20 / Kaisa
- 状态：生效
- 决定：暗房冲印店继续做「冲洗玩法」，下一步是用流体模拟驱动显影化学（T-07）；另做一个新工具专门拯救废片（T-08）。两者共用一套出片引擎：色彩映射表、颗粒、光晕、影调曲线、自动校正和肤色保护（T-12）。
- 理由：调研发现暗房的核心是「冲坏也有意思」，拯救废片的核心是「变好、不翻车」，两件事方向相反，塞进一个工具会互相拖累（T-05、T-06 报告）。出片引擎两边都需要，做一次两边用。
- 放弃：A. 暗房里冲出氛围感（每张图要冲 30～90 秒，不适合想一键救图的人）；C. 暗房转型成救片工具（流体冲洗沦为配角，要和醒图正面竞争）。
- 代价：要维护和上架两个工具。
- 重开条件：真实用户数据显示两个工具的用户高度重合、更想在一个工具里完成；或者维护两个工具的成本明显拖慢迭代。

## D-05 冲印用胶片画幅，小卡用独立构图

- 日期 / 决定人：2026-11-23 / Kaisa
- 状态：冲印画幅生效，小卡取景由 D-06 取代
- 冲印默认保留原图比例。可选 35mm 全格（横 3:2、竖 2:3）、35mm 半格（横 4:3、竖 3:4 的名义比例）和 120 方幅（1:1）。允许拖动及缩放裁剪框，原底片对比与冲印成片使用同一个裁剪区域。
- 小卡外框为 55:85，卡面、卡册缩略图与晒卡图共用 3:4 照片窗。默认完整放入成片。画幅与照片窗有差异时，翻卡前可预览并选择居中铺满，预览保留材质的揭晓悬念。
- 35mm 全格为 36×24 mm，半格实拍尺寸随相机留边而异。120 方幅的实际成像约为 56×56 mm。 [理光 PENTAX 17 规格](https://news.ricoh-imaging.co.jp/rim_info2/2024/20240618_040028.html) · [哈苏中画幅尺寸](https://store-apac.hasselblad.com/en-sg/blogs/medium-format/what-is-medium-format-camera)

## D-06 小卡铺满照片窗，翻卡前可调整构图

- 日期 / 决定人：2026-11-23 / Kaisa
- 状态：生效，取代 D-05 的小卡取景
- 小卡外框为 55:85，照片窗为 3:4。默认居中裁切铺满。画幅差异明显时，卡背提示会裁去两侧或上下，用户可直接翻卡，也可以拖动照片并确认取景。
