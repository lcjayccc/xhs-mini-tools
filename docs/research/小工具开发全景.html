小红书小工具：从想法到挂在笔记下面

小工具就是一个离线运行的网页：你写 HTML/CSS/JS，打成 zip 上传，审核通过后挂到笔记下面，用户点开就能用，不需要下载 App。这一页把流程、官方规范、要准备的东西和坑放在一起。整理时间是 2026-11-18（北京时间），官方文档标注的最后更新日期是 2026-11-13。

完整流程

点左边的步骤看细节。“谁来做”一栏写的是：哪些我能替你跑，哪些必须你本人在手机或网页上操作。

    官方硬规范

    违反这些规范，轻则部署失败，重则页面打开后白屏。以官方在线文档为准 A。

    平台能力（window.xhs.miniTool）

    浏览器原生能力被关掉的那些，平台用自己的 API（接口）补回来一部分。每个接口都有最低客户端版本，调用前要判断方法存不存在，不存在就隐藏入口。

    能力接口最低客户端要点
    发布笔记postNote基础标题 ≤20 字，正文 ≤1000 字；图片 1–18 张或视频 1 个。成功只代表用户点了发布，不代表审核通过
    存相册 / 临时文件saveImageToPhotosAlbum writeTempFile9.42图片类工具的出口，代替“下载”
    本地缓存setStorage 等9.46.0单个 key ≤1 MB，合计 ≤10 MB；localStorage 只当低版本兜底
    文件系统持久文件、分片读写9.49
    评论区互动interactionOpenApi9.49
    窗口信息 / 定位getWindowInfo getLocation9.49只有单次定位；精确坐标不要写进日志或埋点
    振动vibrateShort vibrateLong9.50
    陀螺仪启停与监听9.50代替被禁用的 DeviceOrientation
    关注作者followAuthor getFollowStatus9.51引流的关键
    云存储 内测addCloudStorage 等9.51单批 ≤100 条，单条 ≤64 KB，默认 150 QPS（每秒请求数）
    排行榜 内测submitScore getRankList9.51分数在 ±1,000,000 之间；上传时必须勾选“用户头像昵称授权”
    分享share9.53只在全屏模式可用；每个用户每天每个工具最多 10 次；图片只能私信站内
    WorkerDedicated Worker9.53每页 1 个，页面隐藏 30 秒后会被回收
    赞赏 内测rewardAuthor setCloseRetentionEnabled9.53.3先查发布配置里的赞赏开关再展示入口；回调结果里没有金额
    AI 文本 加白window.xhs.AI加白不支持流式输出；单次 ≤40 条消息、≤12000 字，输出 ≤2048 tokens；输入输出都会过内容审核

    发布表单要填什么

    这些限制在网页端和 CLI 里不完全一样，按网页端的要求准备最稳妥 A 源码核对。

    字段要求说明
    名称≤ 14 字符emoji 一般按 2 个字符算
    一句话简介≤ 14 字符说清楚用途就行，14 个字很短，要提前想好
    图标JPG/PNG · ≤5 MiB · 1:1网页端会自动裁成 512×512
    封面JPG/PNG · ≤10 MiB · 3:4在笔记卡片里，封面比图标更显眼
    代码包ZIP · ≤10 MiB · 解压 ≤30 MiB根目录下直接是 index.html；建议压到 2 MiB 以内
    版本号1.0.0三段数字，不能加 beta 后缀；每次更新都要换新号
    类目单选生活方式 / 休闲玩法 / 图像创作 / 学习知识 / 实用工具 / 娱乐测试 / 其他 D 实测
    权限按需勾选相册照片与视频 / 摄像头 / 麦克风 / 位置 / 用户头像和昵称。没有需要就选“不需要权限”，不要因为省事全选

    准备清单

    打勾状态只保存在你这台设备的浏览器里。标了“已具备”的是我这次实际查过的。

    容易踩的坑

    在普通浏览器里能跑，不等于在小工具里能跑

    容器有 CSP（内容安全策略，限制页面能加载和执行什么），会禁止内联脚本、联网请求和 module 脚本，这些在 Chrome 里都能正常运行。只有本地模拟器、Android 真机、iOS 真机三处都测过才算数。

    脚本写在 HTML 里，或者用了 type="module"

    这是最常见的白屏原因：页面渲染出来了，JS 完全不执行。所有 JS 都放进 .js 文件，用 <script src> 引入，事件用 addEventListener 绑定。如果用 Vite 之类的工具构建，要把输出改成经典脚本，并且编译到 ES2017。

    打包时多套了一层文件夹

    先进入 dist 目录再压缩里面的内容，不要压缩 dist 文件夹本身。否则解压后路径是 dist/index.html，容器找不到入口。

    依赖外部接口的点子在这里做不了

    页面不能直连外网，CDN 不行，自己的后端也不行。查天气、查快递、调用 OpenAI 这类需要实时数据的点子都要放弃，或者改成平台 AI 能力（需要加白）。数据只能随包带上，大型数据集也不适合塞进包里。

    本地 Skill 的规则和官方在线文档对不上

    本地随包基线写的是“Worker 不可用、陀螺仪不可用”，在线文档已经开放了 Worker（9.53 起）和陀螺仪 API（9.50 起）。以在线文档为准，本地 Skill 只能当快照用。localStorage 是否可用，文档自己前后也有矛盾，所以统一用 setStorage。

    审核通过后用户还看不到

    小工具发布后不会自己出现在信息流里，要你发一篇笔记并在笔记里挂载它，用户才能从笔记下方打开。所以每个小工具都要配一篇笔记。C

    CLI 能做的和网页端不完全一样

    CLI 能上传、预览、送审、查状态、改名称和图标，但不能勾选《小工具发布安全规范》协议，也不能配置高级能力，而且没有删除、下架命令。这些要在网页端的 Builder Hub 里操作。用了内测 AI 接口的小工具，目前也只能在网页端上传。

    手机客户端版本太旧

    赞赏要 9.53.3，分享要 9.53，排行榜要 9.51。测试手机先把小红书更新到最新版。另外别忘了，你的用户里也有旧版本客户端，所以每个高级能力都要做降级处理。

    变现现实

    官方目前只公开了一条直接收钱的路：赞赏。它还在内测，要单独开通，回调里拿不到金额，也没有公开的分成或结算规则。变现内测是平台挑人邀请，不接受申请。

    所以比较现实的顺序是：先用小工具给账号引流（工具内可以关注作者，笔记带工具），把使用量做起来，进入平台视野之后争取变现邀请；赞赏开通后再接进去。“工具使用量能换来邀请”这一点是推论，平台没有公布挑选标准。

    还不确定的

    • 你的账号能否发布：接口已通，但只有第一次送审被受理，才能最终确认。
    • 审核标准、审核时长、驳回原因：官方没有公开，只能靠第一次送审摸清楚。
    • 赞赏开通的申请路径和条件：文档没写，可能要进内测群询问。
    • AI 能力加白的群在哪：文档提到“在群内提交 uid”，入口没写。
    • 小红书社区规则（诱导、导流、搬运等）同样适用于挂工具的笔记，详细条款在创作者中心 → 安全中心 → 规则百科。C
